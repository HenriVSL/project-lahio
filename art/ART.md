# KAUPUNKI world art (T02)

All world art is generated by one deterministic Python 3 + Pillow script (no numpy). Never edit the BMPs or
headers by hand: change the generator and run it again. Style: **C "Nordic hybrid"** from `art/explore/`
(STYLE.md), both zooms rendered natively from the same 3-D models.

```sh
python3 art/gen_art.py                    # everything: render (~20 s on 10 cores), sheets, headers, previews, check
python3 art/gen_art.py --check            # check the written files only (exit 1 on failure; the full run also
                                          # exits 1 when its final check fails)
python3 art/gen_art.py --only house_t2,road_   # re-render names starting with these prefixes, reuse the rest
                                          # from art/.cache/sprites.pickle (fast iteration on one family)
python3 art/gen_art.py -j 1 --nopreview   # single process, skip previews
```

## 2. Sprite names (the contract with src/art.h)

Masks `MM` = two digits 00..15 of neighbour bits NE=1 (-Y), SE=2 (+X), SW=4 (+Y), NW=8 (-X).

|---|---|---|

| Water | `water0..2` | shimmer frames (ripple dashes drift ~1.3 px per frame, loops after 3) |
| Shores | `shore01..14`, frames `shoreNN_1`, `shoreNN_2` | corner land bits n=1 e=2 w=4 s=8 (STYLE.md 4); frames match `water1/2` |

| Rapids | `rapids_<x|y|n>_<F>`, F = 0..2 | river tile with RIVER_RAPIDS_BIT: white water churning along the axis around dark granite rocks (hydro site); foam fades at the tile edges so rapids meet plain river cleanly |

## 3. Buildings produced

Rotations: all 4 unless the def has `BDF_NO_ROTATE` (well, water tower, park: r0 only). **M4 rotation policy** (per
variant, `rot_plan()` in gen_art.py): `4` = r0..r3 rendered; `2` = r0 and r1 rendered, **r2/r3 are header aliases of
r0/r1** (the art is front/back equivalent: doors, paths, parking on both long sides, so a 180-degree turn looks the
same); `1` = r0 rendered, square footprints get r1..r3 aliases (orientation-free or 90-degree symmetric art), non-square
ones get **no** aliases (fixed orientation: the def must have `BDF_NO_ROTATE`). Either way every name the code asks for
exists, so the code never relies on the art.h r0 fallback. `_ab_` = abandoned style pass
(desaturated, darkened, boarded/broken windows, rust patches, overgrown gravel). Policy per key in `BUILDINGS`:
`all` = every variant, `v0` = only v0 (art_lot_sprite's v-fallback then shows v0_ab), `None` = never (player-placed).

## 4. Anchors, hotspots, header format

```c
static const ArtSpr sheet_world2_64[] = {
    { "grass0", 0, 0, 64, 32, 32, 32, -1, -1 },          /* name, x, y, w, h, ax, ay, hx, hy */
    { "ind_t2_2x2_v0_r0", 512, 1122, 128, 117, 64, 117, 104, 1 }, ... };
```

- `(ax, ay)`: pixel that sits on the **south vertex of the footprint** (tiles, lots, bridges, power, trees,
  overlays). Draw at `south_vertex - (ax, ay)`. Lot sprites keep their full footprint width (32(n+m) px at 64)
  and are trimmed only at the top; overlays/trees are trimmed to their bounding box (the anchor may lie outside).
- Cars: anchor = car ground centre (STYLE.md 9). Smoke: anchor = puff centre.
- `(hx, hy)`: chimney top inside the sprite for smoke buildings (ind_t2_*, coal_plant, sauna, element_factory, and
  the sawmill burner; M4: every key with "yes" in the Hot column of 3.1); `-1, -1` otherwise. Abandoned variants keep the hotspot (life.cpp should not smoke them).
- Aliases (`rock`, `forest_<kind>`, build/ground rotations) are extra entries with the same rect.
- Tallest reach above a footprint's north vertex: 184 px at 64 (tv_tower), 80 at 32; render.h allows 256/128.

## 5. Adding a building

1. Write a builder in `art_models.py` returning a `Model(name, n, m)` (n x m = the def's w x h at rot 0), front on
   +Y. Use `box`, `gable_body`/`gable_roof`, `hip_body` (+`m_hiproof`), `mono_body`, `Cone`, `Ellipsoid`,
   `HeightField` with materials `m_house` (wood), `m_block` (render/concrete/brick: `wins`, `doors`, `bands`
   with `'text'` sign lettering, `joints`, `brickwork`), `m_brickwall`, `m_corr`, `m_roof`. Windows are
   `(s0, s1, t0, t1)` per face tag. Keep every solid inside the lot (strip sorting), props from `add_*`.
   Set `md.hot = (x, y, z)` (canonical) for a chimney top. Give it a `ground` (`g_lot` with gravel/asphalt
   rectangles).

## 6. Notes for the engine tasks

- **Bridges** (`*_bridge_*`) are taller than a tile (railings, deck fascia drawn below the water line): draw them in
  the object/strip pass like a 1x1 lot, not in the flat ground pass. They contain their own water (frame 0, so they
  do not shimmer). Deck top is 1 px above the land road, markings continue across the tile edges.
- **Power** `power_MM`/`wire_MM` are overlays anchored at the tile's south vertex; draw after the tile's ground and
  lot. X-line wires hang from the upper crossarm, Y-line wires from the lower one, so they always meet the
  neighbour. `wire_MM` other than 05/10 hang to the tile centre without a pole (avoid road crossings that turn).
- **Roads on shore tiles**: road pieces carry grass verges; a road on a shore tile should use the plain road piece
  (shore art is not combined with roads). Bridges need full water tiles.
- **Shimmer**: cycle `water0..2` and `shoreNN` / `shoreNN_1` / `shoreNN_2` together; rivers/rapids use the same
  frame counter. Shores beside a river are drawn with lake-coloured water (one tone lighter than the river: reads as
  shallows along the banks).
- **Overlay mode**: lots drawn as `ground_<W>x<H>_r<R>` (rotation independent, aliased), then the `ovl_R_L`
  diamond per tile (`preview/town_64_overlay.png`).
  F3: `ovl_3_4` (NETC_WET, "a new building here would get water") is a sparse light-blue dither (1 px in 4) so
  it reads as faint next to the solid checker of `ovl_3_3` (wet pipe / watered lot, blue).
- **Water pipes** (F2): in the water overlay draw `pipe_<MM>_<state>` per pipe tile **after** every tile's ground
  and `ovl_` diamond (e.g. a second pass over the visible tiles, or per tile right after its diamond: the tube
  spills 1-3 px over the edge midpoint into the neighbour, and the neighbour's own arm covers the same pixels, so
  either order joins cleanly). MM from the 4 neighbours' `TF_PIPE` (WATER.md 4.1); a set bit always has a
  matching arm in the neighbour, whose half of the joint ring completes the ring. State: wet = in reach, short =
  connected but beyond reach, dry = no source. Nothing tall is drawn in the water overlay (buildings flat).
- **Persistent zone view** (F2, DESIGN 14.4): empty zoned tiles keep `zone_<Z>`. Zone boundaries use the edge pieces
  with a **front-edge rule** so buildings occlude them correctly: after drawing tile T's object (lot / tree / road,
  in the normal back-to-front order), for each of T's two front edges e = 02 (SE, neighbour +X) and 04 (SW,
  neighbour +Y) with neighbour N: if zone(T) != zone(N), draw `zonev_<zone(T) ? zone(T) : zone(N)>_<e>` at T's
  south vertex. The band always lies inside T, so it is drawn after T's own building and before anything in
  front of it; a zone's back boundary is drawn on the outer tile (2 px outside the zone), its front boundary on the
  inner tile. Never draw the back-edge pieces 01/08 over a built lot (they would cross its building); they and
  `zonev_<Z>` (all four edges) are for flat contexts (empty tiles, the overlay mode, the minimap-style legend).
  See `preview/town_64_zones.png` (gen_art.py `zone_layer()` is the reference implementation).
- **Smoke**: spawn `smoke0` at the hotspot, advance frames while rising ~6 px (64 zoom) per frame and drifting right.
- **Strip sorting**: everything stays inside its lot; tall chimneys/towers sit inside the footprint columns.
- **Winter later**: `render_gbuffer` keeps per pixel the face normal, material key and world point; a snow pass is a
  new `shade()` mode that maps up-facing roof/ground pixels to snow ramps and water to ice. No new models needed.
