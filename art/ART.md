# KAUPUNKI world art (T02)

All world art is generated by one deterministic Python 3 + Pillow script (no numpy). Never edit the BMPs or
headers by hand: change the generator and run it again. Style: **C "Nordic hybrid"** from `art/explore/`
(STYLE.md), both zooms rendered natively from the same 3-D models.

```sh
python3 art/gen_art.py                    # everything: render (~20 s on 10 cores), sheets, headers, previews, check
python3 art/gen_art.py --check            # check the written files only (exit 1 on failure; the full run also
                                          # exits 1 when its final check fails)
python3 art/gen_art.py --only house_t2,road_   # re-render names starting with these prefixes, reuse the rest
                                          # from art/.cache/sprites.pickle (fast iteration on one family)
python3 art/gen_art.py -j 1 --nopreview   # single process, skip previews
python3 art/gen_art.py --mockups          # 1.1 W2: render both seasons + write only the winter mockups (no pages)
python3 art/gen_art.py --cached --mockups # the same from art/.cache (no rendering)
```

## 2. Sprite names (the contract with src/art.h)

Masks `MM` = two digits 00..15 of neighbour bits NE=1 (-Y), SE=2 (+X), SW=4 (+Y), NW=8 (-X).

| Water | `water0..2` | shimmer frames (ripple dashes drift ~1.3 px per frame, loops after 3) |
| Shores | `shore01..14`, frames `shoreNN_1`, `shoreNN_2` | corner land bits n=1 e=2 w=4 s=8 (STYLE.md 4); frames match `water1/2` |

## 3. Buildings produced

Rotations: all 4 unless the def has `BDF_NO_ROTATE` (well, water tower, park: r0 only). **M4 rotation policy** (per
variant, `rot_plan()` in gen_art.py): `4` = r0..r3 rendered; `2` = r0 and r1 rendered, **r2/r3 are header aliases of
r0/r1** (the art is front/back equivalent: doors, paths, parking on both long sides, so a 180-degree turn looks the
same); `1` = r0 rendered, square footprints get r1..r3 aliases (orientation-free or 90-degree symmetric art), non-square
ones get **no** aliases (fixed orientation: the def must have `BDF_NO_ROTATE`). Either way every name the code asks for
exists, so the code never relies on the art.h r0 fallback. `_ab_` = abandoned style pass
(desaturated, darkened, boarded/broken windows, rust patches, overgrown gravel). Policy per key in `BUILDINGS`:
`all` = every variant, `v0` = only v0 (art_lot_sprite's v-fallback then shows v0_ab), `None` = never (player-placed).

## 4. Anchors, hotspots, header format

```c
static const ArtPiece art_pieces_64[] = {
    { 3, 128, 0, 32, 41, 0, 76 },      /* page, x, y, w, h in the page, dx, dy inside the sprite box (PL4) */ ... };
static const ArtPSpr art_sprites_64[] = {
    { "grass0", 64, 32, 32, 32, -1, -1, 120, 1 },       /* name, w, h, ax, ay, hx, hy, first piece, count */
    { "ind_t2_2x2_v0_r0", 128, 117, 64, 117, 104, 1, 431, 3 }, ... };
```
(w, h, ax, ay, hx, hy) describe the sprite box exactly as rendered; the pieces only carry its opaque parts.

- `(ax, ay)`: pixel that sits on the **south vertex of the footprint** (tiles, lots, bridges, power, trees,
  overlays). Draw at `south_vertex - (ax, ay)`. Lot sprites keep their full footprint width (32(n+m) px at 64)
  and are trimmed only at the top; overlays/trees are trimmed to their bounding box (the anchor may lie outside).
- Cars: anchor = car ground centre (STYLE.md 9). Smoke: anchor = puff centre.
- `(hx, hy)`: chimney top inside the sprite for smoke buildings (ind_t2_*, coal_plant, sauna, element_factory, and
  the sawmill burner; M4: every key with "yes" in the Hot column of 3.1); `-1, -1` otherwise. Abandoned variants keep the hotspot (life.cpp should not smoke them).
- Aliases (`rock`, `forest_<kind>`, build/ground rotations) are extra entries with the same rect.
- Tallest reach above a footprint's north vertex: 184 px at 64 (tv_tower), 80 at 32; render.h allows 256/128.

## 5. Adding a building

1. Write a builder in `art_models.py` returning a `Model(name, n, m)` (n x m = the def's w x h at rot 0), front on
   +Y. Use `box`, `gable_body`/`gable_roof`, `hip_body` (+`m_hiproof`), `mono_body`, `Cone`, `Ellipsoid`,
   `HeightField` with materials `m_house` (wood), `m_block` (render/concrete/brick: `wins`, `doors`, `bands`
   with `'text'` sign lettering, `joints`, `brickwork`), `m_brickwall`, `m_corr`, `m_roof`. Windows are
   `(s0, s1, t0, t1)` per face tag. Keep every solid inside the lot (strip sorting), props from `add_*`.
   Set `md.hot = (x, y, z)` (canonical) for a chimney top. Give it a `ground` (`g_lot` with gravel/asphalt
   rectangles).
2. (Milestone-2 and later: put builders and rows in the matching `art_m2_*.py` module instead, with a rotation
   policy per variant, see 3, and iterate with `m2_preview.py`.) Add a row to `BUILDINGS` in `gen_art.py`: `(key, (w, h), rotations, [variant builders], ab_policy)`; the key must
   equal `BuildingDef.key`. New footprints automatically get `build_`/`ground_` sprites.
3. `python3 art/gen_art.py --only <key>`, look at `preview/b_<key>_64.png`, then a full run. `--check` prints the
   defs-vs-art variant table; ask T04 to set `variants` to the art count.
4. New colours go into `PAL_BASE` (artlib.py) as a lit base colour (keep them muted; style C desaturates by 0.9).

## 6. Notes for the engine tasks

- **Bridges** (`*_bridge_*`) are taller than a tile (railings, deck fascia drawn below the water line): draw them in
  the object/strip pass like a 1x1 lot, not in the flat ground pass. They contain their own water (frame 0, so they
  do not shimmer). Deck top is 1 px above the land road, markings continue across the tile edges.
- **Power** `power_MM`/`wire_MM` are overlays anchored at the tile's south vertex; draw after the tile's ground and
  lot. X-line wires hang from the upper crossarm, Y-line wires from the lower one, so they always meet the
  neighbour. `wire_MM` other than 05/10 hang to the tile centre without a pole (avoid road crossings that turn).
- **Roads on shore tiles**: road pieces carry grass verges; a road on a shore tile should use the plain road piece
  (shore art is not combined with roads). Bridges need full water tiles.
- **Shimmer**: cycle `water0..2` and `shoreNN` / `shoreNN_1` / `shoreNN_2` together; rivers/rapids use the same
  frame counter. Shores beside a river are drawn with lake-coloured water (one tone lighter than the river: reads as
  shallows along the banks).
- **Overlay mode**: lots drawn as `ground_<W>x<H>_r<R>` (rotation independent, aliased), then the `ovl_R_L`
  diamond per tile (`preview/town_64_overlay.png`).
  F3: `ovl_3_4` (NETC_WET, "a new building here would get water") is a sparse light-blue dither (1 px in 4) so
  it reads as faint next to the solid checker of `ovl_3_3` (wet pipe / watered lot, blue).
- **Water pipes** (F2): in the water overlay draw `pipe_<MM>_<state>` per pipe tile **after** every tile's ground
  and `ovl_` diamond (e.g. a second pass over the visible tiles, or per tile right after its diamond: the tube
  spills 1-3 px over the edge midpoint into the neighbour, and the neighbour's own arm covers the same pixels, so
  either order joins cleanly). MM from the 4 neighbours' `TF_PIPE` (WATER.md 4.1); a set bit always has a
  matching arm in the neighbour, whose half of the joint ring completes the ring. State: wet = in reach, short =
  connected but beyond reach, dry = no source. Nothing tall is drawn in the water overlay (buildings flat).
- **Persistent zone view** (F2, DESIGN 14.4): empty zoned tiles keep `zone_<Z>`. Zone boundaries use the edge pieces
  with a **front-edge rule** so buildings occlude them correctly: after drawing tile T's object (lot / tree / road,
  in the normal back-to-front order), for each of T's two front edges e = 02 (SE, neighbour +X) and 04 (SW,
  neighbour +Y) with neighbour N: if zone(T) != zone(N), draw `zonev_<zone(T) ? zone(T) : zone(N)>_<e>` at T's
  south vertex. The band always lies inside T, so it is drawn after T's own building and before anything in
  front of it; a zone's back boundary is drawn on the outer tile (2 px outside the zone), its front boundary on the
  inner tile. Never draw the back-edge pieces 01/08 over a built lot (they would cross its building); they and
  `zonev_<Z>` (all four edges) are for flat contexts (empty tiles, the overlay mode, the minimap-style legend).
  See `preview/town_64_zones.png` (gen_art.py `zone_layer()` is the reference implementation).
- **Smoke**: spawn `smoke0` at the hotspot, advance frames while rising ~6 px (64 zoom) per frame and drifting right.
- **Strip sorting**: everything stays inside its lot; tall chimneys/towers sit inside the footprint columns.
- **Winter** (1.1 W2): done, see section 9.

## 7. VRAM report (16-bit; `--check` prints the current numbers)

the 64-zoom and 32-zoom world totals separately plus the UI sheets (always resident) and **fails if the 64-zoom
world pages exceed 9.6 MB** (the 32-zoom set has the same limit). PL4 (2026-11-04) cut every sprite into trimmed
pieces on 512x256 pages (section 8): same pixels, much less transparent margin in VRAM.

## 8. Pieces and pages (PL4)

- **Why.** The Voodoo3 driver gives DirectDraw one *linear* heap plus two *rectangular* heaps of exactly the screen
  size (VM B, `tools/vramprobe`: 1024x768 = 9,088 KB linear + 2 x 1024x768 = 2 x 1,536 KB; 800x600 ~11.3 MB +
  2 x 938 KB; 640x480 ~12.8 MB + 2 x 600 KB). A surface taller than the screen can only live in the linear heap, so
  the old 640x2048 sheets refused the 4th 64-zoom sheet at 1024 with 4,477 KB "free" (all of it rect heap). Pages of
  <= 512x256 fit both kinds of heap and leave only small holes when a zoom swap evicts and re-creates them.
- **Pieces.** `sprite_pieces()` cuts each sprite into columns on the half-tile grid (32 px at 64 zoom, 16 at 32) and
  trims each column group to its opaque box. render.cpp draws lot sprites (`LOT_NAME`, anchor on the grid, wider than
  two half-tiles) one strip per half-tile column (centre pair merged), so cuts on those boundaries cost **no extra
  blit**; any other cut costs one blit and is only made when it saves more than `PIECE_LAMBDA` = 600 px. Identical
  pieces are stored once. Result: 64-zoom 9,212 KB of sprite boxes -> 7,485 KB of pieces (packed 7,691 KB).
- **Contract.** The sprite box (w, h, ax, ay, hx, hy) is unchanged, so render.cpp's strip grid, picking and anchors are
  unchanged; code draws world sprites only through `art_draw`, `art_draw_cols`, `art_blit_part` (sprite-local rect)
  and reads pixels through `art_pixels` (multi-piece sprites are assembled in a scratch buffer) / `art_opaque`.
- **Iteration.** `python3 art/gen_art.py --repack` re-cuts and re-packs the cached sprites (art/.cache) in ~15 s and
  runs the check. The PL4 switch was verified pixel-exact: every one of the 2,320 sprites (both zooms) re-assembled
  from its pieces equals the old sheet rect, with the same w, h, ax, ay, hx, hy.

## 9. Winter art (1.1 W2, DESIGN_1_1 section 4)

- **One G-buffer, two shades.** Every job is shaded twice: `normal`/`ab` and `winter`/`ab_winter` (artlib `shade()`).
  The winter pass only recolours, so the alpha mask is identical (run_job raises if not): every sprite keeps its box,
  anchor, pieces and picking, and **one piece table serves both seasons**. Cars are season-invariant (no winter copy).
  Caches: `art/.cache/sprites.pickle` (summer, unchanged format) + `sprites_winter.pickle`.
- **Pieces and pages.** `write_sheets` shares a piece only when it is identical in both seasons, packs once, and writes
  `world<k>_<z>.bmp` + `world<k>_<z>w.bmp` (winter pixels at exactly the summer rects; a page identical in both seasons
  gets no winter file). `art_world.h` lists `art_world_winter[]` (per page: winter BMP or NULL) and
  `ART_WORLD_HAS_WINTER`. Summer pixels are bit-identical to 1.0 (only one 32-zoom piece split; page sizes unchanged).
- **Look** (THEME 3.2, user-approved mockups 2026-11-08): `CUSTOM_RAMPS` snow `#F4F6F8`..`#8597AE` (flat ground one tone
  below a lit flat roof, `SNOW_GROUND_D`; ground shadows lifted to the blue `#BCC8D8`), ice (blue-grey, drift patches,
  all shimmer frames identical), packed snow with grit (gravel roads, yards, paths, rail bed). Solids: up-facing
  (normal z > 0.5) non-glass pixels -> snow, walls unchanged (outlines stay); spruce `spruce_w` with snow bands, pine
  caps, deciduous crowns -> bare twigs with light gaps + snow dabs (rowan berries kept), rock flanks dark with snowy
  tops, ~16 % of plain glass windows lit (`WINTER_LIT_WINDOWS`), power wires dark (`wire_w`). Ground functions read
  `st.winter`: ploughed roads (asphalt `asph_w`, markings hidden, slush ridge, packed edges, snow banks from the road
  distance, so autotiles still match), gravel = packed snow with ruts, rails dark on a grey bed, fields white with
  furrows and frozen ditches, marsh with sedge tussocks, shores with dry reeds in the ice, car parks ploughed with
  banks. Rivers/rapids stay open (dark water, shimmer kept); bridge water is ice. Generic fallback `winter_ground()`:
  `SNOW_GROUND` / `PACKED_GROUND` / `KEEP_GROUND` tables (unknown summer ground keys are listed by the render).
- **Flat marks** (procedural): winter copies with darker colours (same pixels drawn): cursors (`CUR_COLS_W`), zone
  tints (`ZONE_TINTS_W`), zone-view dashes (`ZONEV_COLS_W`), overlay dither colours (`_ovr_winter`, NETC_WET darker).
  Pipes, smoke, fire unchanged.
- **Check** (`--check`): per zoom x season page count/sizes, 24-bit, 565, no near-key, winter alpha == summer alpha per
  page, every sprite re-assembled from the winter pages == its winter render (with the cache), VRAM per zoom x season
  (summer = winter: 64-zoom 7,691 KB, 32-zoom 1,918 KB; the winter copies need the same again in system memory).
- **Mockups** (`preview/`): `*_winter.png` for every town view, overlays (pollution, land value, water), zone view,
  `cursors_<z>_winter.png` (cursor marks + lot ghosts on snow), the M2 towns, review sheets; `cmp_*.png` summer|winter.
- **Engine** (src/art.cpp): `art_set_season()` re-uses the same surfaces. Plan A keeps the other season as a per-page
  delta (runs of differing pixels: 3,887 KB instead of 9,609 KB); step 1 swaps the resident pages' px (VM B 37 ms),
  step 2 on the next frame uploads them (31 pages at z64: 128-141 ms; 8 at z32: 32 ms); the other zoom's pages catch
  up when they become resident. Plan B (process memory over `ART_HEAP_BUDGET_KB` = 40 MB) reads pages from disk
  (~850 ms on VM B); Plan C = INI `winter_art=0` or missing pages. Process memory on VM B: 19.8 MB before the art,
  30.0 MB with it (1.0), 34.0 MB with the winter delta. render.cpp polls `season_is_winter()` (or `-winter` /
  `-summer`, script `artseason 1|0|-1`) each frame and flushes chunks, ghost copies and minimap colours after a swap
  (ui.cpp rebuilds the minimap); lakes/shores do not shimmer in winter. VM test: `scripts/w2_shots.txt`,
  results in `tests/out/w2/`.
